# GRACE-GC

## What This Is

把《GRACE：ICLR 论文框架 v3》实现为可复现、可审计的 RLVR 研究代码库，供作者开发主方法、运行核心对照并检验 Learning–Answer Gap（LAG）是否存在且值得利用。第一版交付完整 GRACE 主方法、核心对照和最小证伪流水线；大规模确认性实验、扩展消融和论文写作后置。

当前 Windows 本机不具备真实实验条件：先完成代码、CPU 数学/小模型验证与部署准备，再到 GPU 服务器运行最小证伪。目标硬件是当前 4 张 A100，未来两组各 8 张 RTX 5090。

## Core Value

在保持完整轨迹原始策略梯度目标和真实成本账本的前提下，让研究者用最小可信实验判定 GRACE 的关键假设成立、被否定或证据不足。

### 主方法与目标

原始目标 G=(R-b)∇θΣ log π，θ 是全部 q/v LoRA A/B 参数。前缀预测 m=Uf；以实际记录的 p 抽 Z，再用 Ghat=m+Z/p·(G-m) 补全。每批预先固定起步数 N，单次 actor 更新，绝不以随机完成数或自归一化权重替代 N。

预测器、基底、基线、策略在整批内冻结。选择 RNG 不读取后缀或奖励，审计 RNG 独立；停止样本 reward=null。风险目标是全空间残差，包含基底正交补与实际 Gram 矩阵。

机制轨道保持同一原始梯度目标；实用 GRPO 轨道保留独立目标并单独标识。原始梯度无偏不等于 clipping 后或 Adam 位移相同。

## Constraints

- **科学目标**：不改变 token-sum、全 LoRA 参数空间、历史基线和固定起步分母以追求更好结果。
- **时间顺序**：先交付代码，再运行最小证伪；GPU 不可用不阻塞 CPU 可验证代码实现。
- **技术栈**：Python + NumPy 数学参考 + PyTorch 小模型/actor；服务器遵循论文的 verl + vLLM + FSDP 路线，版本锁定以官方发布源码和实际兼容验证为准。
- **依赖隔离**：核心包不强制导入 CUDA、verl、vLLM；CPU 与 GPU 依赖分组，禁止因 GPU 依赖缺失把核心验证一起跳过。
- **数据隔离**：按 problem_id 分开训练、预测器训练/风险标签、校准、审计、最终评测；历史训练信息不能来自当前后缀。
- **真实账本**：部署成本按预留 GPU 数乘墙钟记录，重叠不能重复累加；研究成本另计，CPU verifier 另报。
- **结果诚实性**：未运行 result=null、status=planned；统计证据不足不得自动判 Go；性能目标不能转写为观测值。
- **验证限制**：CPU/mock 检查不能替代 FSDP/AMP、vLLM RNG、吞吐和显存的目标硬件验证。
