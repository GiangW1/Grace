# GRACE-GC

## What This Is

实现《GRACE：ICLR 论文框架 v3》的主方法、核心对照和实验脚本。首轮代码与真实单卡最小实验已完成；当前按实验暴露的问题继续修复和验证，论文的实际效率主张尚未获得支持。当前版本与下一步见 [STATE.md](STATE.md)。

## Core Value

用尽可能简单、正确、可运行的代码实现论文方法，让实验尽快回答方法是否值得继续。

## 工作方式：奥卡姆剃刀

2026-09-15 用户明确纠正：代码优先，然后最小证伪；不要加奇怪的门槛影响实验。该要求替代之前六阶段流程、43项形式化需求和待审批路线图。

- 实现以函数、普通数据结构、配置文件和脚本为主；只在确实有两个不同后端时抽取必要接口。
- 规划是简短的工作清单，不设独立“研究合同阶段”。
- 不建额外的审批流、实验准入系统、多维状态机或通用决策器。
- 模型和数据可使用本地路径或公开标识；运行时尽量保存实际 revision/版本，未填可选元数据不阻止试跑。
- 实验统计量按实际样本计算。样本少、结果不好、区间宽时照常输出；不附加最低样本量/置信区间宽度门槛。
- 论文原有的统计定义和目标值保留为分析参数或对照说明，不变成程序的开关。
- 代码问题边实现边修；理论疑点边记录边研究，不要求解决全部理论问题后才能写代码。
- 必要的数学、数值和集成检查随实现进行；无 GPU 的测试在服务器补跑，日志如实说明。

## 必须实现正确的数学内容

原始目标 G=(R-b)∇θΣ logπ，θ 覆盖全部 q/v LoRA A/B。预测 m=Uf，续写 Z~Bernoulli(p)，估计量 Ghat=m+Z/p·(G-m)。每批分母为预先确定的起步数 N。

预测器/基底/基线/actor 在当前批保持不变；选择 RNG 与后缀和审计分开。风险包含全空间残差和实际 Gram 项。标准梯度下降优化器使用负 Ghat。机制对照共享该目标，GRPO 保留其独立目标。

这些内容决定是否实现了 GRACE，保留相应测试。输入文件不可读、概率非法、维度不匹配等实际错误需清楚报错；论文的效果目标不参与这些检查。
